# Agent 历史来源准入（临时保护）

Agent 的模型上下文会重放旧答案、工具输出和压缩摘要。现有消息引用不能证明新轮次的改写与旧来源独立，因此逐条删除受限引用不足以阻止跨轮次传播。

本次先实现实例级准入：只有数据库中保留的来源证据检查均为空，才允许加载 Agent 模型历史。检查包括软删除数据源、包括已删除 KB 的粘性 `ever_had_nextcloud_source` 标志，以及配对记录、中止墓碑和独立 `nextcloud_source_tombstones`。缺表、查询失败、非法标志值、缺少检查能力均关闭准入。全局范围覆盖跨租户共享 KB 和 Agent 工具范围变化。

PG132／SQLite51 增加的独立墓碑没有业务行外键。全局、租户和 KB 来源判断会读取已保留的正向证据，数据源、KB 或配对行硬删除后仍会阻止旧历史准入。SQLite／PostgreSQL 回归覆盖业务证据硬删除后的三种来源判断与墓碑表缺失。

保留证据为空不证明实例的全部旧历史从未接入来源：若所有旧证据已在迁移回填前彻底删除，回填无法重建它们。逐消息 legacy NULL 仍需按未知来源实施完整读取／重放策略；这一策略尚未启用。这个实例级 fallback 不能作为完整历史来源证明。

准入发生在读取压缩摘要和历史分页之前，并在返回模型消息前复检。摘要读取失败或非空但格式无效会排除历史；服务记录原因并用空历史继续本次提问，同时关闭本次旧记忆注入和历史摘要写入。普通无 Nextcloud 实例仍按原有 token 预算、checkpoint 和工具压缩规则重放历史。

隔离验证：固定 c6 与 RAG77 两个基线均运行 AgentHistoryAdmission、LoadAgentHistory、NextcloudGlobalHistory 测试。覆盖旧受限轮次落在新分页范围外、新答案无引用改写、压缩摘要、查询失败、源配置改变时的二次检查，以及普通无来源实例摘要重放。

这是一项临时保护。它会拒绝已接入 Nextcloud 实例的 Agent 多轮历史；它不实现逐轮依赖图、完整压缩摘要来源、长期记忆来源或普通 RAG 的跨轮次传递来源。普通 RAG 传递来源和过滤后分页仍需专门修复与验收。完整派生物 GC 继续受现有 blocker 限制。

## 保存消息和 SSE 重连

保存的 Agent 答案、真实工具轮次和压缩摘要通过同一个实例级准入检查，覆盖 GetMessage、消息列表、最近/更早消息和消息搜索配对；用户文本仍可从消息列表读取。合成 `ragpipe-*` KnowledgeQA 时间线以及其 SSE 原始调用 ID 映射不被误判为真实 Agent。宽 KB 与 legacy tenant 来源检查现在也读取粘性标志及 pairing/abort 证据；缺少持久来源检查能力返回不可用。

SSE 对完成行使用历史检查，对未完成行使用正在运行的文档/KB 权限检查。重连会吸收引用与 search/read/list/graph 工具结果中的文档 ID，并在同批后续内容帧之前复检。尚无引用且只含准备工具调用时，隐藏工具参数并继续检索；来源内容或不透明图结果不走这个分支。严格结构的空图结果仍检查先前文档引用。缺少 SSE 验证器失败关闭。

StopSession 和 steer 使用单独的所有者元数据查询。此查询拒绝空 owner、调用者与执行租户不一致或返回会话所有者不一致，且不返回内容、引用和工具输出；不需要读取已撤回文本才能停止运行。公开消息读取继续检查未完成行的保存内容。

## 验证证据与剩余范围

两个固定基线的完整 access/service/session 测试及 SQLite 全局/KB/tenant 来源测试均通过。Docker 测试网络禁外连，`example.com` 与 `api.e2b.app` 使用容器内固定公网地址映射，仅满足既有 SSRF DNS 单元测试；服务提供者使用测试 stub。之后两个基线的针对性历史/SSE 回归及 PostgreSQL 来源证据测试在临时内部网络、tmpfs 数据库中通过，未连接共享数据库。日志保存在隔离工作区 `dist/agent-history-{c6,rag}-{final,focused-pg}.jsonl`。

本次不证明完整来源版本链。普通 RAG 的跨轮次传递来源，以及完成答案/缓存流正文与原始 ETag 的绑定仍缺失：如果同一 knowledge ID 被重新索引、当前行更新为新 ETag，仅核对该行与来源当前版本不能证明旧答案或旧 SSE 正文是新版本。此风险也影响未完成流中已缓存的旧正文，需要事件与答案保存来源版本快照。权限完整性与版本完整性不能混同。

消息列表当前先读取固定分页再过滤拒绝的助手行；过滤后短页可能被前端当成历史结尾。恢复可靠游标或安全占位是独立待修事项。长期记忆、工作区产物、普通 RAG 的传递依赖、完整派生物 GC 及真实 AD 验收继续未完成。

全局准入是保守临时 fallback：实例一旦曾接入 Nextcloud，就排除 Agent 历史上下文；本次新提问继续使用空历史生成，正在运行的工具结果仍检查当前权限。实际 AgentQA 回归覆盖来源曾存在、来源查询失败和检查能力缺失，确认引擎收到本次用户提问且没有旧历史、旧 checkpoint 读取或摘要写入。保存的 Agent 来源不明结果仍隐藏。这不是完整 V1 权限链路验收。

仅清空消息历史不能阻止 Agent 从以前的工作区读取副本。因此历史被拒绝或无法验证时，本次运行不恢复历史 session 附件，且不接入已有 sandbox 文件/exec、skills、会话搜索、旧记忆、MCP 或本地浏览器能力。新提问和本次上传附件仍进入模型；当前带权限检查的文档检索以及普通新回答可以继续。运行时 `ExcludeHistoricalContext` 字段不从用户 JSON 或保存配置读取，限制也不修改用户的持久 Agent 配置。验证为从未接入 Nextcloud 的普通实例保留原有工作区和历史能力。

工具级回归先用正常引擎实际读取/exec 已有工作区文件中的受限标记，证明测试后端确实能返回旧正文。随后用历史隔离配置执行同样的模型工具请求，确认文件读和 exec 调用均为零，旧标记没有进入工具结果、模型上下文或答案，而本次新回答仍输出。该隔离不提供长期记忆写入、历史产物下载 API 或一般派生物的完整 lineage；这些仍属于待实现范围。

保留的 session 能力准入独立于 `MultiTurnEnabled`。关闭消息重放也不能自动授权旧工作区、附件、记忆或历史工具，因此所有 AgentQA 都先执行同一实例来源检查。入口回归覆盖两个多轮开关值与来源曾存在、查询失败、缺失检查能力、明确无来源四种状态，实际模型请求旧文件 read/exec：前三种状态无后端读/exec、无旧附件恢复、无旧正文且新回答继续；明确无来源的对照在两种模式下仍能读取既有工作区。测试同时检查关闭多轮的用例没有被默认值改为启用。
