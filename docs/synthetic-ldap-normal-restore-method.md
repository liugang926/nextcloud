## Inputs and clean sequence

Use the exact scratch and candidate manifest provided for the newly built normal image. The manifest is an immutable **private 0600 snapshot**, not the mutable repository manifest. Its bytes and actual image IDs/role/source labels are pinned. The existing history probe receipt must be private 0600 and contain its actual `project`, `session_id`, and `completed_history_count`; the probe rereads those messages and never treats receipt booleans as evidence. Evidence directory is owner-only 0700, canonical, and outside fixture controls.

The following are command shapes, **not executed results**. Set task-specific variables to the exact provided paths and profile; no guessed project or old fixture receipt is supported.

```sh
python3 scripts/ops/synthetic-ldap-normal-restore.py \
  --scratch "$RESTORE_SCRATCH" --candidate-manifest "$RESTORE_MANIFEST" \
  --profile "$RESTORE_PROFILE" --evidence "$RESTORE_EVIDENCE" \
  --phase checkpoint --baseline-history "$RESTORE_HISTORY"
```

Run the same four common arguments with these phases, in order:

1. `fault`: reopen the same pinned candidate solely for the real unpublished file and personal-session fault, recheck the original source and drain, then stop actors again.
2. `restore-data`: actual dual full `pg_restore` plus original data-volume restoration; keep CURRENT anchors. Cluster roles must still match. Clear only the exact owned WK Redis queue; SQL153 intents are authoritative, although this drained clean checkpoint proves no pendingAuto recovery.
3. `closed-clean`: packaged body reconcile → verify, complete original source inventory capture/compare, original model/permission/generation tuple and independent CURRENT publication pin checks. Add `--body-upgrade-authorized` only after the body owner declares a required packaged upgrade; unsupported upgrade modes fail closed.
4. `reopen`: repeat real closed gates, NC-only current source authorization, absence of the real post-checkpoint fault file/session, then controlled WK/model/DocReader/UI start; original Alice session/history/admissions/body heads/native replays/citations plus first post-restore QA.
5. `revoke`: actual source-only group-share revoke; old and new original history/replay/citation redacted and new generation denied; LDAP identity and KB grants retained.
6. `cleanup`: available only after the full clean positive/revocation gates. Exact owned Compose resources may then be destroyed, including anchors at this **final cleanup**, never during rollback. Private backups/receipts/external publication anchors remain for review. Shared services and Go module/build caches are untouched.

Every backup and receipt is exclusive-create 0600, every phase event is append/flush/fsync, and failed artifacts remain. The runner does not retry a partially written backup over the original output or automatically erase diagnostics. Tar archives reject traversal, absolute links, and device/FIFO entries. Storage helper containers have no network and use 1 CPU / 512 MiB. The fixture's actual app resource settings are unchanged. The P5 sender now keeps an exclusive private `active-probe-workers.json` marker through its 5-second sleeps and removes only its exact marker after its thread has really joined. Restore rejects that marker; a worker crash leaves it for actual terminal/ownership review instead of silently inferring that the sender is gone.

This proves only the closed branch **when actually executed**. It does not claim restored original history remains readable after a real later withdrawal, and does not re-sign old bodies or citations as a fresh source generation. Future reopening must explicitly resume NC publication, run real WK signed pair/double-complete current manifest reconciliation, ingest new knowledge IDs with real backend indexing, verify actual current source/personal permissions, and prove old-generation denial. This preparation deliberately provides no stale reopen/cleanup bypass.

## Auto153 pending-intent recovery interface

`--phase pending-auto-plan` writes a private interface receipt with `accepted: false`. It never seeds SQL task/admission/manifest rows. A separate live probe must configure genuine Auto tags and Summary/QA through the owned tenant APIs, submit a new eligible source file through real DAV + signed delivery/ProcessSync, and capture a real completion boundary with `parse_status=completed`, exact sealed SQL intent/payload/model/body manifests, no terminal receipt, and an actual broker outage or process exit before delivery. A timer expiry without a previously actual claim cannot stand in for process death.

Required artifacts are exact knowledge/admission/generation/source scope; real pending/running claim; immutable payload digest; queue/model body heads; actual broker/process terminal; prior tags/publication receipt absence; and source/actor/model withdrawal negatives. Restore both real databases/storage while retaining CURRENT body/publication anchors and empty only the owned Redis queue. Reopen only after actual offline source/body gates. Startup SQL recovery must deliver the saved payload, publish once, produce one terminal receipt, and reject an old task after actual source/actor/model withdrawal. A drained checkpoint in this runner is **not** acceptance of that behavior. The existing machine durability suite is component evidence, not full normal-app restore evidence.
